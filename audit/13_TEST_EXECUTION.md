## Coverage quality

The strongest tests exercise real rules, deliberate transport interruption, durable receipt/journal state and fixture parity, and check expected numeric or persisted values. Mocked storage/auth unit tests establish application decisions without exercising actual persistent caches, independent tabs, real token refresh or process death. Rules tests include verified and unverified owners, cross-account denial, partial updates, malicious shapes, delete policy, recurring receipts and restore revision conditions. They still need end-state regressions for category migration and rollback with an existing future-dated revision and absent baseline preferences.

The main missing regressions follow the findings register. Include an actual paste through both web forms, an Android edit/delete surviving an offline sign-out attempt and process restart, two devices editing different fields, recurring backlogs above the batch cap plus a standalone receipt, an interrupted replace after preference commit, and a release gated SHA differing from a moved tag. The chapter reports specify concrete inputs and expected outcomes. No application-source or existing test-source changes were made.

The repository suite uses serial test files but enforces deadlines within each file. The timeout in `web/emulator/backupReplace.test.ts:510` left an async restore running when the next tests started, causing four secondary `RESTORE_OPERATION_ALREADY_IN_PROGRESS` errors. Record elapsed emulator fixture/cleanup time and isolate or abort an outstanding operation after a timeout before starting the next scenario. The two concurrent runs used separate emulators and ports. Host contention and asynchronous cleanup limit the interpretation of the observed timeouts.

## Local execution incident

The first Android command failed to enter its intended temporary directory before it copied the CI JSON. That overwrote the ignored workspace `app/google-services.json`. The audit reconstructed its Android build inputs from the pre-audit generated debug and release resources and restored the ignored config. An isolated Gradle 9.7.1 run of `processProdDebugGoogleServices processProdReleaseGoogleServices --offline --no-daemon` regenerated all seven Firebase resources identically in both variants before the restore. The original JSON bytes and any unused metadata could not be recovered. This procedure did not contact the live Firebase backend.
